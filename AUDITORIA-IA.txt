[1] INYECCIÓN EN CONSULTAS ARCGIS
Archivo: app/components/ExpedientSearch.jsx
Línea aproximada: dentro de fetchSuggestions()
Problema:
  La cláusula WHERE se construye interpolando directamente la entrada del usuario:
    const where = `(UPPER(TENURE_ID) LIKE '${limpio}%' OR UPPER(CODIGO_EXPEDIENTE) LIKE '${limpio}%')`
  Solo se escapan comillas simples (' -> ''). Los caracteres comodín % y _
  NO se escapan, lo que permite manipular el patrón LIKE.
Corrección recomendada:
  Escapar también % y _ antes de insertarlos en la consulta:
    const limpio = query.trim().toUpperCase().replace(/'/g, "''").replace(/%/g, "\\%").replace(/_/g, "\\_")
  O mejor aún, usar parámetros parametrizados si el servicio ArcGIS los soporta.

[2] DEPENDENCIAS DUPLICADAS O DESNECESARIAS
Archivo: package.json
Problema:
  Se detectan pares de paquetes que hacen lo mismo:
  - "@shadcn/ui" y "shadcn-ui" (dos paquetes distintos; probablemente solo se usa uno)
  - "geojson2shp" y "@mapbox/shp-write" (ambos exportan SHP)
  - "epsg-to-proj", "proj4-list" y "proj4" (posible redundancia en manejo CRS)
Corrección recomendada:
  Buscar con grep qué paquetes se importan realmente en el código.
  Desinstalar los que no aparezcan en ningún import.
  Esto reduce el tamaño de node_modules y del bundle final.

[3] TYPESCRIPT ESTRICTO DESACTIVADO
Archivo: tsconfig.json
Línea: "strict": false
Problema:
  Con strict desactivado, TypeScript no detecta valores null/undefined,
  tipos implícitos any, ni muchos errores silenciosos comunes en código generado por IA.
Corrección recomendada:
  Cambiar "strict": true en tsconfig.json.
  Si genera demasiados errores al inicio, activarlo progresivamente:
    1. "noImplicitAny": true
    2. "strictNullChecks": true
    3. Finalmente "strict": true

[4] FALTA next.config.js
El proyecto usa Next.js pero no tiene archivo de configuración.
No es bloqueante, pero impide personalizar imágenes, headers HTTP,
rewrites, redirects o variables de entorno públicas.
Corrección recomendada: crear un next.config.js básico si se necesita alguna de esas opciones.

[5] SCRIPT OBSOLETO verify.py
Archivo: verify.py (raíz del repositorio)
Problema:
  Busca un botón con texto "Aplicar":
    await page.click("button:has-text('Aplicar')")
  Pero el botón real en ExpedientSearch.jsx dice "Buscar".
  El script falla siempre que se ejecuta.
Corrección recomendada:
  Eliminar el archivo o actualizarlo para que busque el botón correcto:
    await page.click("button:has-text('Buscar')")

[6] ERRORES SILENCIADOS EN test_perf.js
Archivo: test_perf.js (raíz)
Problema:
  Bloques catch vacíos: catch (e) {} ocultan errores reales sin información.
Corrección recomendada:
  Al menos imprimir el error: catch (e) { console.error(e); }

[7] COMPONENTES DEMASIADO GRANDES

APLICADO
  [2] Dependencias. El informe sospechaba tres pares duplicados y dejaba el
      grep pendiente. Hecho: eran OCHO paquetes declarados que el código no
      importa en ninguna parte —tokml, geojson2shp, epsg-to-proj, proj4-list,
      shapefile, shpjs, @shadcn/ui y shadcn-ui—. Arrastraban 136 paquetes.
      Al quitarlos, las alertas de seguridad pasaron de 23 a 12, y las
      críticas de 4 a 1.

      utils/exportUtils.js; el SHP lo hace @mapbox/shp-write, que se conserva.
      Comprobado en el navegador que KML y SHP siguen descargando bien.

  [5] [6] Archivos obsoletos. Borrados verify.py y test_perf.js, y también
      benchmark.js, que al informe se le pasó. No eran solo ruido: los dos
      últimos llevaban los índices de capa de la ANM escritos fijos (1,2,3,4),
      que es la trampa nº1 documentada en CLAUDE.md.

PENDIENTE, PERO NO COMO LO PROPONE EL INFORME
  [1] NO es una inyección: las comillas sí se escapan. Lo que hay es que % y _
      funcionan como comodines, y teclear "%%%" pasa el mínimo de tres
      caracteres y barre el dataset nacional. Es un problema de CARGA, no de
      seguridad.
      *** NO APLICAR la corrección que propone. *** El replace(/%/g, "\\%") no
      funciona: en SQL la barra invertida no es escape por defecto, hace falta
      una cláusula ESCAPE. Tal cual, rompería las búsquedas normales.

  [4] Cierto que falta next.config.js, pero el informe lo llama "no
      bloqueante". Es al revés: ahí van las cabeceras de seguridad de un sitio
      público, y hoy el visor sale sin ninguna. Sube de prioridad, no baja.

  [3] Cierto, pero poco rentable: el proyecto es JavaScript casi por completo
      y "strict" solo afecta a cuatro archivos .ts/.tsx.

LO QUE EL INFORME NO VIO
